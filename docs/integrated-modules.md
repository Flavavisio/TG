# CRM and Assist within Total Gest

CRM and Assist now open in the application's central workspace. The company sidebar, header, notification bell and home action remain in the main shell. Existing module pages run in same-origin frames to retain their forms, reports and persistence without introducing conflicting globals. In embedded mode, the module's navigation becomes a horizontal tab strip, and its duplicated company sidebar/back links are removed. Existing standalone URLs remain compatible.

All cards, sidebar links, favorites, Nexus shortcuts, dashboard alerts and customer assistance actions use the internal routes. Dashboard/customer links that create an OS retain their assistance ID. The customer workspace closes when navigating into Assist. Module saves notify the host to refresh the relevant canonical tables; this is skipped while host changes are unsaved or a host form is open, leaving the existing regular synchronization to refresh later. Clean modules reload on re-entry; open forms or unsynchronized changes remain in their current frame.

Access retains the existing profile/card restrictions and checks the base company license and the module's own active subscription. Assist is granted by the current Pro and Supreme packs; CRM by Supreme. Individually active subscriptions continue to work. CRM no longer implicitly grants Assist. Pack configuration and prices are unchanged. Standalone Assist also checks its own subscription. The embed checks its host frame, same origin and account before loading/displaying or saving. Frames are removed on logout, account change or revocation, and access is checked periodically for expiry. No tokens are passed through messages; existing Supabase clients and RLS remain responsible for database access.

Validation: `tests/integrated-modules.test.cjs` covers pack grants/downgrades, module expiry, base-license expiry, roles/hidden cards, actual main navigation, deep links, preserved shell, account changes, frame authorization, denied saves after revocation filtered save synchronization, actual module initialization/forms with mocked Supabase responses, and protection against an old account refresh overwriting the new account. Existing Nexus, assistance/portal and billing tests also pass. Live authenticated Supabase workflows and visual browser layout have not been tested in this environment.
